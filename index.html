THE METHOD

A small edit.
A separate test.

Observe a failure, investigate its mechanism, and modify the policy. Development feedback guides the edit; inaccessible held-out layouts test the frozen result.

—charged development episodes
—held-out layouts

Infrastructure refunds mean the charged budget is not an exact count of attempted episodes. Source inspection is permitted; these experiments do not certify independent discovery.

What counts as an edit?

Hand-written changes and closed-form fits from forward-pass data are allowed. Gradient-based fitting, fine-tuning, and LoRA are not. Gradients may be used for diagnosis, not to optimize the edit.

Diagnostic interventions are not the final policy: the submitted change must be saved in the weights.

What does the comparison ask?

Python + curated toolkit versus Python alone: both agents can inspect model internals, use hooks and replay, write their own mechanistic analyses, and save weight edits. The full-tool agent is a superset: it can use the packaged tools, write custom Python, or combine both.

Python-only removes ready-made analyses, not interpretability. Black-box agents also deliver weight edits, using behavioral feedback and action-bias editing. This is a tool-suite ablation, not a no-weight-edit baseline.

Strong Python-only results support the broader weight-editing approach, not the necessity or superiority of the curated toolkit. Different counts, controls, and selected cohorts prevent a simple causal ranking.

CURRENT IMPLEMENTATION

From policy to evidence.

A development harness for investigating pretrained policies: explicit adapters connect the policy and simulator to an LLM-driven laboratory. The deliverable is a validated, saved weight edit—or the unchanged base policy—not a diagnostic intervention.

New harness, unchanged research snapshot.

The architecture below describes the current implementation, including the optional fork controller. The 35 historical held-out comparisons below predate this upgrade; no policy gains are attributable to the upgrade yet. Research experiments are paused. Harness verification includes 222 CPU tests and 493 source differential cases; these are engineering checks, not new scientific results.

01 / Bring a policy and a task

A pretrained VLA, WAM, or other learned policy enters through a policy adapter declaring streams, hook sites, action semantics, capabilities, and editable parameter scopes. A benchmark adapter supplies layouts, rollouts, recordings, and task outcomes.

Interface-generic does not mean zero-code compatible. Each policy–simulator pairing needs explicit adapters and a preflight check. Tools unsupported by the declared capabilities are omitted rather than assumed to work.

02 / One agent, the full Python superset

An LLM in Codex CLI exchanges tool calls and evidence with the MCP laboratory. FULL offers both arbitrary Python and curated tools: the agent can use the full Lab object, NumPy, and PyTorch to inspect parameters, use hooks, replay recordings, write analyses, and save edits.

Curated tools add matched controls, activation analysis, causal interventions, attribution, and saved-edit recipes; they do not replace custom code. Python-only retains the raw ingredients through RawLab, but removes ready-made analyses. Codex shell, browser, and nested-agent features are disabled in this configuration.

03 / Evidence before selection

Falsifiable hypotheses link each candidate to its parent and an immutable candidate snapshot. Recorded development evidence supports diagnosis; screens and activation interventions are exploratory, not final submissions. Full-cohort repeats validate eligible improvements before selection.

The harness selects the best eligible development improvement, or keeps the base policy when none qualifies. Persistent notes, tool logs, candidate lineage, and episode accounting preserve what was tried—not just the winning score. Replay does not imply deterministic simulator physics.

04 / Freeze, then evaluate independently

The selected weights are frozen before a separate evaluator compares base and edited policies on paired held-out layouts. The agent never sees held-out results. There is no held-out feedback path into search or candidate selection.

Reporting checks cohort completeness and identity. Native-pipeline and side-effect checks provide additional validation; they are not universal guarantees. The current prototype submits weight edits only: closed-form fits and diagnostic gradients are allowed, but gradient-based fitting, fine-tuning, and LoRA are not.

OPTIONAL SEARCH CONTROLLER

Fork, validate, resume the winner.

--search-mode fork-flush creates four isolated, fresh workspaces (K = 4), currently executed in sequential waves. It selects the best validated lineage, resumes the winner in the same conversation, and repeats at the aggregate 33% and 66% development-episode budget boundaries. Losing branches count toward the same aggregate budget. The default remains sequential flush-only search.

Scope and provenance of the optional controller

Joint eight-direction portfolios and balanced six-of-ten robot-metric views reuse components from the official RSI-top implementation. This is not the full RSI treatment: semantic deduplication, execute-all, and stall monitoring are not implemented. Merging and retrieval remain future work.

No author Fork-and-Flush implementation was found; this controller combines independent MIT-licensed helpers with the paper’s algorithm. Its software checks do not establish gains in policy performance.
