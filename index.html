THE METHOD

A small edit.
A separate test.

Observe a failure, investigate its mechanism, and modify the policy. Development feedback guides the edit; inaccessible held-out layouts test the frozen result.

—charged development episodes
—held-out layouts

Infrastructure refunds mean the charged budget is not an exact count of attempted episodes. Source inspection is permitted; these experiments do not certify independent discovery.

What counts as an edit?

Hand-written changes and closed-form fits from forward-pass data are allowed. Gradient-based fitting, fine-tuning, and LoRA are not. Gradients may be used for diagnosis, not to optimize the edit.

Diagnostic interventions are not the final policy: the submitted change must be saved in the weights.

What does the comparison ask?

Python + curated toolkit versus Python alone: both agents can inspect model internals, use hooks and replay, write their own mechanistic analyses, and save weight edits. The full-tool agent is a superset: it can use the packaged tools, write custom Python, or combine both.

Python-only removes ready-made analyses, not interpretability. Black-box agents also deliver weight edits, using behavioral feedback and action-bias editing. This is a tool-suite ablation, not a no-weight-edit baseline.

Strong Python-only results support the broader weight-editing approach, not the necessity or superiority of the curated toolkit. Different counts, controls, and selected cohorts prevent a simple causal ranking.

THE FULL AGENT HARNESS

Inside the full agent.

One reasoning agent, two complementary ways to investigate: custom Python and a curated interpretability toolkit. A policy-aware laboratory connects both to the model, recorded evidence, and simulator.

01 / Agent execution

Codex CLI supplies the reasoning/tool-call loop and context management. A per-run driver supplies the task, baseline summary, episode budget, and any edit-scope restriction, and can resume the same thread after interruption. This is one research agent per experiment—not a planner–coder–critic swarm.

In this configuration, the agent’s code execution is the laboratory’s python tool. Codex shell, browser, and nested-agent features are disabled; custom analysis code is not.

02 / Full capability, not a fixed recipe

The full agent can call curated tools, write new analysis code, or combine both. Its Python environment exposes the full Lab object: model parameters, hooks, recorded episodes, replay, analysis methods, and lab.save_edit.

The Python-only ablation uses the same Python execution mechanism but exposes a RawLab view without the ready-made analyses. It retains the raw ingredients for interpretability and weight editing.

03 / Policy-aware laboratory

Each backend declares model streams, hook sites, output/action semantics, supported capabilities, and editable parameter scopes. Generic tools use those declarations rather than assuming every VLA or WAM has the same architecture. Unsupported tools are not registered.

Recordings include actions, robot state, camera data, model inputs, noise seeds, and activation summaries. Replay supports targeted interventions and richer activation capture for diagnosis; it is not a claim that all simulator physics is deterministic.

04 / Evidence and evaluation

Development rollouts consume the episode budget. The run retains tool-call logs, notes, figures, and an edit manifest. A diagnostic activation intervention is not itself the submitted policy: the final change must be saved as parameter edits.

After the agent run finishes, a separate runner evaluates the original and edited policies on paired held-out layouts. Reporting checks cohort completeness and identity before accepting a result. Native-pipeline and side-effect checks are additional validation, not assumed guarantees.
